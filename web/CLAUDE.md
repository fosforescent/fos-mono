# web - CLAUDE.md

## Directory Summary
Vanilla-TS task client used in the browser and wrapped by the Tauri desktop/mobile app (`desktop/`). Offline-first: the replica (a FosStore from `shared/sync`) lives in localStorage and merges with the account or another device when connected. Design: `docs/sync.md`.

## Files
- `src/main.ts` - entry; dev-only auto sign-in from `VITE_API_USERNAME/PASSWORD`, never in production bundles
- `src/app.ts` - controller: stored session restore, attachment lookup, sync scheduling (account over HTTP, direct over WebRTC, manual relay), connect/invite/direct flows
- `src/ui.ts` - DOM rendering from app state. **Workflowy-style tree**: there is no add bar; a blank "ghost" row at the top of the view (`renderGhostRow`, not in the replica until typed into) is where the cursor defaults (`focusGhost`), Enter makes it the first row (`App.addRowAtTop`, marker parsed) and opens a row below, ↑ from the first row returns to it. The selected row is an inline editor (click or arrow to it); ↑/↓ move between rows, Enter adds a blank row below, Ctrl+Enter marks a task done (other rows: new row below), Ctrl+Shift+Enter adds a row inside, Tab/⇧Tab indent, Alt+↑/↓ move, Alt+→ zoom in, Alt+← zoom out, Backspace on a blank row deletes it (Ctrl+Shift+⌫ deletes any), Esc leaves, Ctrl+. opens the `⋯` context menu (also right-click), **Ctrl+H toggles the keys/syntax help modal** (`KEY_HELP` + `SYNTAX_HELP`; also the `?` button and the menu). Rows without children show no bullet; only notes keep the `·`. Depth shown at once comes from `maxDepth()`: phones (<640px) show one level and rows with children get a `›` zoom chevron; larger screens expand/collapse 2–6 levels in place depending on height. HTML5 drag-and-drop above/below/into, link panel (members, versions, proposals, presence dots), the **context panel** (`renderContext`: banks in scope, peers with capability chips, assignments per peer), hamburger menu with the red `local` badge, Connect/Invite/Requests/Direct/Help modals (QR via `qrcode`, scanning via `html5-qrcode`), and the *Approve a sign-in* modal opened by `?device=CODE` (a `fos login` in a terminal waiting for this browser)
- `src/api.ts` - backend calls (login, peer-sync, attachment, invites, connect polling, WebSocket events)
- `src/p2p.ts` - WebRTC host/guest with offer/answer codes, sync over the data channel, manual relay codes
- `src/storage.ts` - localStorage adapter: replica, prefs, session (token only)
- `src/rows.ts` - row markers (`parseRowInput`; the list the help shows is `SYNTAX_HELP`): `[ ]`/`[x]` task (`[ ] `name` …` executes a template), `>` note, `//` comment, `-<kind>` requirement where the kind names the child row that fills it (`-[ ]` task, `-$ 50` money / `-: 1h` time / `-# 2 widgets` things / `-@bob` a person, `-?` search, `-market`, `-mail`, `-choice: a | b`, plain `-` confirmation), `$` / `:` / `#` / `@name` allocations with an optional window after the amount (`parseWindow`), `?` query, `@calendar|@money|@inventory|@person name [capacity]` resource bank, `` `name `` template, otherwise a plain row. `rawRowText` rebuilds the marker form for editing; `allocationTag` the tag shown on a parent row; `RESOURCE_MARKER`/`RESOURCE_ICON`; amount parsing/formatting, link/image/YouTube rendering, file download
- `src/notes.ts` - note blocks: frontmatter + child-row variables (`key: value`, titled children, refs to other blocks), `{{key}}`/`{key}` expansion, lists, `.md` export
- `src/markdown.ts` - marked + DOMPurify; KaTeX (`$…$`, `$$…$$`) and Mermaid (```mermaid fences) are dynamic imports loaded on first use
- `src/project.ts` - project mode inside Tauri: finds `fos.config.toml` (`find_project`), keeps state in `<dir>/.fos/` through `read/write_project_file`, follows git branch switches

## Conventions
- The UI never sees content addresses; it reads `viewNode` output (alias ids, titles, flags).
- Rows have a `kind` (`task | plain | note | comment | ref | requirement | supply | query | resource | allocation | template`, see `docs/sync.md`); only tasks are checkable, and a task with unsatisfied requirements has a disabled checkbox and a `needs n` badge. A task executing a template carries `template{id,name}` (badge `` `name ``). Any row can be zoomed into, invited to, or attached to by a device; there is no "partition" concept.
- Editing shows a row's raw marker text (`rawRowText`) and re-parses the whole text on commit: `App.rewriteRowAt` → `setRowContentAt` rewrites kind, text and data in place (id and children kept); allocations resolve their bank through `App.allocationWithBank`/`bankFor` (nearest bank of the type above, the requirement's resource, else the type's default pool = first top-level bank; a person allocation needs a bank only with a window). Each row has a `◉` zoom dot left of the drag handle. Allocations under a row show as tags on it; unmet requirements (and executions/templates with unmet ones) get the `unmet` red mark, allocation requirements a green progress bar (`requirement.have/need`). Dropping an allocation on a requirement supplies it; dropping a template executes it inside; "Add @name as a member" in the menu makes a row a group (`App.addPeerToRow`, fos joins as a member the first time). The blank top row keeps focus after Enter (no extra blank row).
- Rows with controls (requirement, supply, query, resource, allocation) keep their body when selected (`renderSpecialBody`: Confirm / choice buttons, "Ask fos to search", "List on the market", "Done (confirm)" for the assigned peer, allocation picker, Search/Refresh, bank balance); double-click or Enter edits their text. Typing a `-`/`?`/`@`/`$`/`` ` `` prefix into a blank row converts it (`App.convertPlainRowAt`); `[ ] `name`` applies the template (`App.applyTemplate`). Allocations resolve their bank from the parent context (`App.bankFor`: bank above, else the bank of the requirement's resource).
- Root and Home: the app starts in Home (view `[]`, the replica). Zooming out of Home (Alt+←, Backspace, the `root` crumb) sets `state.atRoot` and `renderRootRows` draws the device's root as tree rows: a Home row and one row per peer from `App.contextPeers()`: the account server (`fos`, with `state.serverCapabilities` from the last sync response, `SERVER_CAPABILITIES` before it; Sign in on its row when not connected; its to/from policy lines), Home's members (capability chips = what Home's owner exposes to them; the owner clicks a chip to switch it off/on, × to remove, "+ add" to add, the "Add peer" row to make another account a member with `edit`: `App.setPeerCapabilities`/`addPeerHere`/`removePeerHere`) and attached devices (`direct` when direct-connected). Chips show as offline when the peer is. There is no context panel; banks are rows in the tree. `App.askPeerAt` hands a search/market requirement to the peer that registered it.
- Fos points: `ff 20` allocates, `-ff 20` requires; `state.points` is the account's token balance (`getTokenBalance`, refreshed after each account sync, shown on the fos row); an `ff` allocation with no `@points` bank draws from it (`resource: 'fos:points'`). Integration peers (`INTEGRATION_PEERS`) appear at the root with provides/consumes chips and a Sign in button that only reports that SSO is not configured yet. `kindPreview` shows a badge after the ghost row's and the editor's input saying what the typed line is recognized as (`describeParsed`).
- Row menu seeds: "Add requirement inside: money/time/things/person/…" and "Add allocation inside" open a row that starts with the marker (`App.addRowInside(at, id, 'plain', seed)`); "Add bank below" seeds `@money `; "Add @name as a member" makes the row a group.
- Allocation bins: "Send to @owner (…) as a proposal" in a row's menu (`App.sendRowTo`) posts the row with its requirement/allocation/task/comment children through `submitMarketProposal` to a node of that account this one knows (`App.knownListings()`: market result refs); the receiver approves it in the link panel.
- Peer policies (`state.policy`, a `PeerPolicy` towards the account server): from `[server] to/from` in fos.config.toml in project mode (`policyLocked`, chips shown locked) or saved in prefs (`App.setServerPolicy`), `DEFAULT_DEVICE_POLICY` otherwise. Enforced in `syncNow` (no round without `from: read`; `buildSyncRequest(…, { push: false })` without `to: autopush`, so nothing local leaves), `mayPropose()` (`to: edit` gates `sendRowTo`/`submitProposal`) and `readsRequests()` (`from: read-requests` gates the proposals list). Member rows show both directions (`to` = capabilities, `from` = accepts, `App.setPeerCapabilities(id, to, disabled, accepts)`).
- Market: "List on market" (context menu, signed in) flags a row; query rows can "Search the market too"; a hit from another account is a ref row with `refOwner` that opens the **Market listing** modal (`state.market`, `App.openMarket`/`submitProposal`): the owner's rows, the requester's own proposal, a comment box and a picker per allocation requirement over `App.allocations()`.
- Drag and drop: plain drag moves, **Alt+drag places a reference** (row shows the 🔗 icon), **Ctrl/⌘+drag places a deep copy** (⧉). Modifier keys are read at drag start.
- Voice notes: the 🎙 button records with `MediaRecorder` and posts the blob to `POST /user/data/voice-notes` (needs a session); the result becomes a parent note (summary) with a note per sentiment cluster, its points as plain rows, and a transcript note.
- Icons: `public/favicon*.png|ico`, `apple-touch-icon.png`, `icon-192/512.png`, `site.webmanifest` are generated from the tree logo (`frontend/logo3-bare.ico`, 256px, the largest copy in the repo).
- Replica operations return a new replica object; always use the returned value.
- `tsconfig.json` deliberately omits `erasableSyntaxOnly`/`noUnused*`/`verbatimModuleSyntax` so the graph code in `shared/` compiles.

## Running
```bash
cd web && VITE_API_URL=http://localhost:4000 npx vite --port 5199
```
